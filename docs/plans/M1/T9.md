## Details

**T9 Page capture.**
- Playwright Chromium, 30 s navigation timeout.
- Waits: `networkidle` with a 15 s cap, then a 1.5 s settle. A lazy-load scroll to the bottom in viewport steps, then back to the top. A placeholder poll (visible text matching `/^loading\b/i`, `[aria-busy="true"]`) until it clears or the 15 s cap is reached. Anything still pending goes to `pendingContent`, and its placeholder text is excluded from facts.
- Screenshots: full page at 390×844 and 1440×900.
- HTML: `page.content()` after the waits.
- Trackers are blocked by a small host list. Fonts, images and same-page third-party embeds still load.
- iframes: `src` is recorded, never navigated into (rule 6).
- In fixture runs, a navigation that ends on the lockdown sinkhole (its 403 page, or a non-empty `escaped` list from `newLockedDownContext`) is a failed navigation, never page content (T4 review).
- **Bot challenge** (`cf-mitigated: challenge` header or the challenge page title): stop the page with `bot-challenge` and never try to get past it.
- Assets are uploaded through an injected `Storage` interface (side effect at the edge).
- **Asset owner (consultant decision, 2026-11-09):** `Asset.siteId` is required, so the crawl job creates a stub Site (business name from the project, `pages: []`) before uploading the first screenshot or HTML asset; T13 fills it in. No schema change.
- **Request-level guard (deferred from T8 QA, 2026-11-11):** `guardedGoto` checks only the final URL after Chromium has already followed redirects, and Chromium resolves DNS itself. T9 installs a `context.route` guard before any navigation. The guard checks every request (navigations, redirect hops, subresources, page `fetch`). Navigations and redirect hops of the main frame must pass consent, origin and path scope. Subresources may come from third-party hosts, so fonts, images and embeds still load as the bullet above says, but they must pass the private-address check and the tracker list. `guardedGoto` requires a context that already has this guard installed.
- **No DNS rebinding gap (consultant, 2026-11-11):** `context.route` sees URLs, not the addresses Chromium connects to. So the route guard does not `continue()` requests to real hosts: it serves each allowed request with `route.fulfill` from the T8 pinned fetch path (checked address, connection pinned). Only the fixture `.test` host map (non-production) may bypass this.
- **Requests routing doesn't see (consultant, 2026-11-11):** create contexts with `serviceWorkers: 'block'`, and block WebSockets with `routeWebSocket` or an equivalent.
*Acceptance:* against T6 fixtures: the delaware feed content is captured (and with the script disabled, `pendingContent` has one entry and no "Loading recent projects..." text appears in facts); `pattern-iframe-booking` records the provider origin with no request into it; `pattern-bot-challenge` ends `blocked`; a navigation whose redirect hop targets another origin or a private address is aborted before the request leaves, and `guardedGoto` refuses a context without the route guard; a hostname that resolves public at check time and private at connect time is never connected to (rebinding test); a page that registers a service worker or opens a WebSocket gets neither.
