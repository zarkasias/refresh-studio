## Details

**T20 Scoring.** `scoring/weights.ts` is one config file with a comment explaining every weight, and `weightsVersion` is stored. Each score starts at 100. Deductions per failed check are by severity (high 25, medium 10, low 4), capped per check, then combined with tool inputs:
- **Works on phones:** our phone-layout checks plus Lighthouse mobile viewport and font-size audits.
- **Easy to contact:** the T16 and T17 checks.
- **Speed:** 70% Lighthouse mobile performance score, 30% image-weight.
- **Accessibility:** axe violations by impact (critical 10, serious 6, moderate 3, minor 1, per rule), plus h1 and contrast. The Lighthouse accessibility score is stored, not scored.
- **Looks current:** deterministic only in M1 (D2): https, dead-links, dated-copyright, placeholder-text, font-count, no viewport meta.
`recomputeScores(auditRun, dismissed)` is the single implementation used by T3's guard (D5). CLI: `pnpm --filter audit run-audit --capture <id>`. *Acceptance:* snapshot tests over fixture captures; the same inputs give identical scores on every run; no import of `@srs/agents` or any LLM SDK (lint rule).
