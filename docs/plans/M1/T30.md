## Details

**T30 Report editor and approval.** `/projects/[id]/report`. Shows scores, read-only, each with a "how we measured this" list of contributions. The consultant can:
- Edit each finding's sentence and why-it-matters, and the summary and what's-working lines.
- Move findings between Fix now and Can wait (the sixth is blocked with a message).
- Dismiss a finding with a reason, which recomputes the scores deterministically (D5).
- Toggle annotation crops.
- Preview at phone and desktop width.
- See a badge when `draftSource: 'template'`.
Edits use `saveEdit` semantics, so an edit after approval creates version n+1. **Approve** goes through `approveReport` (which runs `assertReportApprovable`) in the server action, never `approveReportVersion` directly, and sets `approvedAt`/`approvedBy`. A score drops only when every failed finding of that check is dismissed (ADR-008); the editor says so ("this score changes once all N findings for this check are dismissed"), and the acceptance test for "a dismissal changes the score" uses a check with a single finding. **Mark as sent** creates a `ReportDelivery` (approved versions only). *Acceptance:* e2e covers edit → approve → edit again (new draft; the share link still shows the approved version), the blocked sixth fix-now item, and that a dismissal changes the score and is listed in the version.
