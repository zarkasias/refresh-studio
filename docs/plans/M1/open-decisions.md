# M1 section 11. Open decisions

Part of the [M1 plan](../M1.md).

| # | Decision | Proposed default | Reason |
|---|---|---|---|
| D1 | Font raw + normalized shape | **v3 `extractedFonts: { family, raw? }[]`** with a migration step (ADR-007) | Keeps the raw evidence next to the normalized name in the one model exporters read; the alternative (raw only in capture records) splits the source. |
| D2 | "Looks current" score inputs | **Deterministic checks only in M1** (https, dead links, dated copyright, placeholder text, font count, viewport); LLM visual notes may appear as text, never as score inputs | CLAUDE rule 2 outranks the skill's "model judgment"; T38 fixes the skill. |
| D3 | Report format and delivery | **PDF of an approved version, emailed by the consultant, is the gate path; private share link built and switched on once hosting is decided** | Meets the gate with no hosting cost or deployment risk. |
| D4 | Report approval model | **ReportVersion following ADR-005 (frozen, newest-only, numbered), on a generic versioning core** | One approval pattern across the product; already proven by tests and a DB trigger. |
| D5 | Can the consultant change scores? | **No direct edits; dismissing a finding as a false positive (with a reason) recomputes deterministically and is recorded on the version** | Scores stay tool-derived (rule 2), but a client never sees a penalty we've admitted is wrong. |
| D6 | Make kadence-blocks and beaver-builder known page builders | **Yes, add both to `KnownPageBuilderSchema`** | Both are in the test set; exhaustive switches in detection and exporter path selection need them; no data changes. |
| D7 | Dead links: external links | **Never requested. Static rules only (defunct-service host list, malformed, `#`/`javascript:` non-toggles, missing same-page anchors); same-origin links from crawl status plus up to 50 guarded HEADs, not counted as pages** | Rule 6 forbids leaving the domain; HEADs on the consented origin are cheap and stay inside the guard. |
| D8 | Synthetic fixtures "built from the labels" vs ADR-004 "pattern, never content" | **Anonymize labels first (T5), amend ADR-004 in ADR-010** | Gets label-shaped fixtures without copying client content into a second form. |
| D9 | Lighthouse coverage | **Every crawled page, mobile and desktop, one run each, sequential** | Matches PRD "per page"; reproducible from stored results; about 20–30 minutes of job time is acceptable. |
| D10 | Where the worker and app run; share-link hosting (carries M0 D10) | **M1: worker and app local on the consultant's machine with the Inngest dev server; host only when switching on share links (Netlify/Cloudflare free tier or Vercel Pro $20/mo; worker on a small VM about $5–20/mo)** | Nothing in the gate needs hosting; avoids paying before it's useful. |
| D11 | Crawler identity and robots edge cases | **Real Chrome UA plus token `SiteRefreshStudio/0.1 (+https://www.chambers-consulting.dev/scan)`; robots 4xx = allow, 5xx/error = block the run; honor `Crawl-delay` ≤ 10 s** | Sites render as visitors see them while we stay identifiable; failing closed matches rule 6. Needs a short `/scan` page on chambers-consulting.dev (user). |
| D12 | How strict "conflicting hours" is | **Fire only when the same day has different open or close times in two entries of the same scope; different formats, missing days, and emergency/kitchen/brunch/holiday/24-7/location scopes don't conflict; unparseable text never fires** | Catches cafecito and stays silent on jolly, northern-heights and delaware. |
| D13 | iphci page builder | **Consultant checks View Source for `fl-builder`/`bb-plugin`; if absent, change the manifest to no `pageBuilder` and the fixture expects plain WordPress** | The manifest says beaver-builder with only `wp-content/uploads` as evidence, and M0 said "builder unknown". |
| D14 | Thresholds: contrast and tap targets | **Contrast via axe (4.5:1 normal, 3:1 large text, WCAG AA); tap targets 44×44 px, worded as "too small to tap easily", not a WCAG failure** | axe is the standard tool; 44 px matches rule 7 and the skill; WCAG 2.2 AA itself only needs 24 px, so we don't claim a violation. |
| D15 | Phone number locale | **US/NANP only (`libphonenumber-js`, region US)** | Every test site and prospect is US; other formats are out of scope. |
| D16 | Content mapper in M1 | **No LLM mapper in M1 (PRD puts it in M2); `eval:mapper` scores the deterministic business extraction now, with section scoring wired but `n/a`** | The audit needs business facts, not sections; keeps the M1 scope on the gate. |
| D17 | Can a prospect's site become a test fixture? | **Only with a separate, explicit yes in the consent request; recorded as manifest `granted`** | Consent to an audit isn't consent to keep their pages in our repo. |
| D18 | Retention of prospect scan data | **Delete captures and screenshots after 90 days if the prospect doesn't engage; keep the approved report; delete everything on request** | Collect only what we need, and it's an easy promise to make in the consent request. |
| D19 | Auditor model and cost | **Use the current Claude model named in the API docs at T23; log tokens; flag runs over $0.50** | Rule 3 holds whatever the model; a cost flag keeps eval runs cheap. |
| D20 | Who writes the plain-English text | **Templates write every finding sentence (catalog); the auditor LLM writes only the summary, the why-it-matters lines and the fix-now order, limited to known finding ids and numbers; the consultant edits all of it** | Findings stay reproducible and jargon-free; the LLM adds interpretation where it helps (rule 2) and the pipeline still works without a key. |
| D21 | Owner for site-model and new apps (carries M0 D11) | **Closest specialist, flagged, architect reviews (T1–T3, T27)** | Same as M0; revisit with a `platform-engineer` if M2 adds more cross-cutting work. |
