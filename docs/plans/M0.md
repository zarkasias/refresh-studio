## 1. Goal and gate

**PRD (Milestones):** "M0 Foundation | Repo, site model schema, Claude Code kit, hooks, test set of 10–15 sites | **Schema holds up against test set**"

M0 is done when all of these hold:

1. From a clean clone, `pnpm install && pnpm typecheck && pnpm lint && pnpm test` exits 0 at the repo root. This covers `apps/web`, `packages/{site-model,capture,audit,agents,sections,brand}`, `packages/exporters/{wordpress-theme,style-guide,astro-site}` and `evals`. CI runs the same commands on every PR.
2. `packages/site-model` exports Zod schemas (with types inferred from them) for every entity in section 2. There is no `any` in public APIs. A Drizzle schema and a generated SQL migration are committed.
3. `evals/sites/manifest.json` lists 10–15 sites, each with platform, evidence, business type and consent status. It validates against a Zod schema.
4. At least 10 sites have a hand-labeled `evals/sites/<slug>/expected.site.json` (homepage plus contact page at minimum), and all of them pass `SiteSchema` inside `pnpm test`.
5. **Misfit log is empty or resolved.** Each fixture has a `misfits[]` list in the manifest for content that could not be represented honestly. The gate passes only when every misfit was fixed by a schema change recorded in ADR-003, or was explicitly accepted by the consultant.
6. `packages/brand` exists. `apps/web` renders a studio shell styled with it. A test proves that `packages/sections` (and exporters/agents) **cannot** import it.
7. ADRs 001–004 (section 7) are committed to `docs/decisions/` with status `accepted`.

**Follow-up for the user (not a task):** once item 1 passes, re-enable the typecheck hook. The current working copy of `.claude/settings.json` has no `hooks` block at all, so this means adding it back. Running a full `pnpm typecheck` on every Edit/Write gets slow across 11 workspaces. A `Stop` hook, or a filtered `pnpm -r --filter "...[HEAD]" typecheck`, may be nicer.

## 2. Changes to the site model (these come first: T3)

| Change | Why |
|---|---|
| `Project { id, clientName, siteUrl, consent?: Consent, createdAt }` and `Consent { grantedBy, grantedAt, method: 'email'\|'signed'\|'own-site', scope: { origin, pathPrefix?, maxPages ≤ 25 }, evidenceAssetId? }` | Rule 5 relies on `project.consent`, but no Project type is defined anywhere. `pathPrefix` is needed for shared-host sites such as `*.wixsite.com/<name>` (rule 6). |
| `Variant.approvedAt?: string (ISO)`, `Variant.approvedBy?: string`; also `assertShareable(v)` | Rule 4 requires an explicit `approvedAt`, and Variant only has `status`. |
| `Site.schemaVersion: 1` | Fixtures and future migrations need it. |
| `Site.platform`: add `'other-hosted'`, plus `platformDetails.builder?`, `platformEvidence: { signal; where: 'html'\|'header'\|'asset-url'\|'footer-text' }[]`, `platformConfidence: 0–1` | Several test sites run on hosted builders outside the enum (BentoBox, ChiroPlanet). `custom` should mean hand-coded. Capture must be able to store its evidence. |
| `platformDetails.pageBuilder`: add the literal `'wpbakery'` (keep `\| string`) | Seen in the test set. |
| `business.locations?: { label?, address?, phone?, hours?, googleBusinessUrl? }[]` (top-level fields stay as the primary location) | Multi-location businesses in the set. Needed for the PRD's name/address/phone consistency check. |
| `hours?: { label?: string; text: string }[]` (raw text, not parsed) | Lets the audit flag conflicting hours (seen in the set). |
| `Section.type`: add `'menu'` | Restaurant menus are not `pricing`. |
| `cta.kind`: add `'order'`; add `cta.provider?` (e.g. `toast`, `meevo`, `phorest`) | External ordering/booking tools appear on 4 of 13 sites. |
| `Asset { id, siteId, kind: 'image'\|'logo'\|'font'\|'screenshot'\|'document', sourceUrl, storagePath?, width?, height?, bytes?, alt? }` | The model refers to `*AssetId` everywhere but never defines Asset. `alt` feeds the a11y checks. |
| Concrete leaf types: `HexColor` (`^#[0-9a-f]{6}$`), `GoogleFont { family, weights }`, `extractedColors: { hex, role?, share? }[]`, `socialLinks: { network, url }[]`, `Version.snapshot: { site; variant }` | These are untyped today. |

**Not changed:** the Section list beyond `menu`, and DesignTokens.

**Storage shape (ADR-003):** `projects`, `variants`, `versions` and `comments` are relational tables. The `Site` document is stored as JSONB with `schemaVersion` and validated by Zod at the edges.

**T1 Workspace scaffold.** Files: `package.json` (scripts `typecheck`, `lint`, `test`, `test:e2e`, `eval:mapper`, `eval:auditor`, `dev`), `pnpm-workspace.yaml` (`apps/*`, `packages/*`, `packages/exporters/*`, `evals`), `tsconfig.base.json` (strict), `eslint.config.mjs`, `.prettierrc`, `vitest.config.ts` (`test.projects`), `.nvmrc`, `.gitignore`, `.env.example`. A minimal Next.js App Router app goes in `apps/web`. Each package gets `package.json`, `tsconfig.json`, `src/index.ts` and one smoke test. Use the "internal packages" pattern: `exports` points at TS source and Next uses `transpilePackages`.
*Acceptance:* the clean-clone command chain exits 0. Unscoped names are unique, so `pnpm --filter capture …` resolves (`/audit-site` depends on this). `eval:*` scripts print "no eval cases until M1/M2" and exit 0. `engines` and `packageManager` are pinned (D3).

**T2 CI.** GitHub Actions runs install, typecheck, lint and test on PRs to `main` and `dev`, with a pnpm store cache. *Acceptance:* a green run on a PR, and a deliberately broken type makes the run red.

**T3 Site model v1.** Implement section 2 as Zod schemas in `src/schemas/*.ts`, with types from `z.infer`, and export `needsReview(section)` (confidence < 0.7). *Acceptance:* unit tests for valid and invalid cases of every entity, the hex regex, confidence bounds and `schemaVersion`. `docs/site-model.md` updated in the same PR.

**T4 Guards.** Pure functions: `assertCrawlAllowed(project, url)` (consent present, same origin plus `pathPrefix`, maxPages ≤ 25), `assertShareable(variant)` (`approvedAt` set), `assertExportable(variant)` (`status === 'selected'` and `approvedAt`). *Acceptance:* tests cover missing consent, a cross-origin URL, a wixsite path outside the prefix and a 26th page. All of them throw with plain-English messages.

**T5 Drizzle.** Tables: `projects` (consent columns), `sites` (JSONB doc), `assets`, `variants` (`approved_at`), `versions`, `comments`. `drizzle-kit generate` output committed. *Acceptance:* a Vitest test applies the migrations to **PGlite** (in-process, no Supabase) and round-trips one fixture Site.

**T6 Manifest.** `evals/sites/manifest.json` plus Zod schema: `slug, url, businessType, platform, builder?, platformConfidence, evidence[], whyUseful, consent: 'own-site'|'granted'|'requested'|'none', consentRecordedAt?, misfits[]`. Seed it with section 4. Add `evals/mapper/history.json` and `evals/auditor/history.json` as `[]` (the `/eval` command expects them). *Acceptance:* the manifest validates, and a test asserts that no network-using eval can select an entry whose consent is `none` or `requested`.

**T7 Consent outreach (user).** Email the owners of sites you want as HTML fixtures (start with M1 prospects) and record the replies. Doesn't block M0. Blocks M1 HTML/screenshot fixtures.

**T8 Labeling (user).** For each site, view it in a normal browser as any visitor would (no automated fetch) and hand-author `expected.site.json` for the homepage and contact page. Log anything that doesn't fit in `misfits[]`. About 15–20 minutes per site, 3–4 hours total. agent-engineer provides a blank template and may draft labels only for `own-site` and `granted` entries.

**T9 Conformance.** `evals/sites/conformance.test.ts` validates every `expected.site.json` and prints the misfit summary. *Acceptance:* gate items 4–5 hold.

**T10 Brand package.** `packages/brand/{src/tokens.ts, theme.css, assets/}`. `tokens.ts` is a typed object. `theme.css` uses a Tailwind v4 `@theme` block with every variable prefixed `--studio-`. Fonts load in `apps/web/app/layout.tsx` via `next/font`. *Acceptance:* the values come from the source of truth (D4a), with no estimates. A unit test checks AA contrast for each studio text/background pair. The logo has meaningful alt text ("Chambers Consulting").

**T11 Boundary.** Three layers:
- pnpm isolation: `@srs/brand` is not a dependency of sections, exporters, agents or site-model.
- ESLint `no-restricted-imports` blocks `@srs/brand`, `apps/*` and `**/brand/**` in `packages/{sections,exporters/*,agents,site-model}`.
- A Vitest test runs the ESLint API on a fixture file that imports brand from inside `packages/sections` and expects an error.

*Acceptance:* the negative test passes, and `grep --studio-` across `packages/sections` and `packages/exporters` returns nothing.

**T12 Studio shell.** Root layout with a studio header (logo plus "Site Refresh Studio"), a placeholder `/dashboard` and a placeholder `/review/[token]` chrome. Add a code note that the variant canvas renders in an **iframe** in M2. One Playwright e2e smoke test against the local app, plus an axe pass on both routes. *Acceptance:* `pnpm test:e2e` passes locally with no serious or critical axe violations.

**T13 Kit alignment (user).** Add allow rules for `pnpm install`, `pnpm --filter *` and `pnpm exec drizzle-kit *`. Consider restricting the `playwright` MCP server (in `settings.local.json`) so it isn't used to browse non-consented test sites.

## 8. Risks and out of scope

**Risks**
- Labeling effort (T8, about 3–4 consultant hours) is the critical path to the gate.
- Set bias: polished-leaning, light on WP page builders and dated sites.
- Platform labels drift (2 of 4 roundup labels were already wrong). M1 detection must re-verify.
- Overfitting the schema to 13 sites: keep changes generic.
- Third-party content in the repo: keep it private and minimal.
- Shared hosts: "same domain" must mean origin plus path prefix.
- Brand asset quality: gradient raster logo, no confirmed hex or font values. T10 is blocked on D4a.
- CSS bleed between studio chrome and the variant canvas.
- Hosting cost and runtime for the studio (D10).

**Out of scope for M0:** any crawling, Lighthouse/axe runs against client sites, platform detection code, LLM agents or API keys, the Supabase project, Inngest, deployment, Puck/GrapesJS, section components beyond a stub, exporters, client review functionality (chrome placeholder only).
